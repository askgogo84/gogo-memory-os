## Review regressions and guarantees

`scripts/verify-runtime-fencing-review.mts` executes real exported runtime plus real approval-binding/TTL with snapshot-faithful inert persistence. It covers terminal completed/failed/unknown replans, cancellation after step-start, old attempt/backoff reuse, interrupted/cross-run/replaced approval release, normal active execution/replan, missing approval suspension plus exact-bound resume, zero-row completion, same-attempt metadata races, cancellation during replan, same-run different-action substitution, changed payload, expired/future approvals, expiry before dispatch and approval discovery on initially ungated work.

The first review RED recorded seven failing groups and a passing normal-flow control. Independent same-run approval review added a separate failing substitution case. Further REDs exposed same-attempt metadata races and false unknown classification before provider dispatch. GREEN preserves all original assertions. Strict existing fixtures gained explicit pure-dependency declarations, JSON-path/null filter semantics and a reconciliation-race trigger tied to actual completion rather than a fixed read count. No expected safety outcome was weakened.

Approval metadata alone is not authority. Concrete handlers must stage/display an explicit action shape; unbound legacy approvals fail closed. Release and dispatch use existing fingerprints, owner/run/step/tool/idempotency/objective/plan input/revision, requested time and expiry. Rejected preflight is definite no-dispatch, not a fabricated unknown provider effect. Runtime cannot replace concrete adapter validation or revoke an already sent external request.
