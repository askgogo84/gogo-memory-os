# Hachi adaptation — 8mynd shared AskGogo and SecondBrain architecture
Date: 2026-11-28. Reviewed baseline: 1322e29aaae0564ae186198f0a09110122019b06. Hachi source tree: 6004b7a91d0d70296592b11c4c238dda87e041e6 (tree identifier, not a release pin). No upstream code imported; Apache-2.0 implementation, CC BY 4.0 specification/paper; comply with respective attribution/notice terms for any future copied work. No new runtime dependency.

## Decision
Do not replace Same Brain, the existing TypeScript registry, Supabase memory, existing permission controls, provider adapters, or workspace isolation. Hachi is local-first/single-principal; do not treat its gateway token, local vault, or memory guard as enterprise multi-tenant security. Keep user and workspace data isolated by server-verified identity, membership, exact IDs and current access. No public onboarding or provider activation. Existing approved work and #1660 dated facts remain separate. No SQL, configuration, secrets, cron or deployment changes here.

## Evidence and gap analysis
- [Hachi](https://github.com/OpenGigantic/hachi): versioned typed .og skills, bounded retrieval, ReAct loop, local-first permissions, integrations, memory vault and diagnostics. Pre-release per README.
- [ObjectGraph benchmark](https://github.com/OpenGigantic/hachi/blob/main/docs/reference/benchmark.md): 12,150 versus 248 estimated tokens on a bundled library and a naive dump-all baseline; 36 probes including five negatives; approximate tokenizer; compare against OUR existing retrieval and cached prompts, multilingual quality and actual bills before claiming savings. README cites a different 97.6% figure; not a forecast.
- [Memory guide](https://github.com/OpenGigantic/hachi/blob/main/docs/guides/memory.md), [gardener](https://github.com/OpenGigantic/hachi/blob/main/src/hachi/core/memory_gardener.py), [memory guard](https://github.com/OpenGigantic/hachi/blob/main/src/hachi/core/memory_guard.py): atomic fact extraction, dedup and reviewable supersession; regex scanner is defense-in-depth, not sufficient against multilingual or encoded attacks.
- [Single-tenant ADR task](https://github.com/OpenGigantic/hachi/blob/main/docs/audit/2026-07-19/tasks/T-61-single-tenant-adr.md) describes historical gateway auth limitation; do not reuse single-principal auth for a shared service.
- Current skill-registry.ts defines SOP semver, schema, capabilities, approval and cost/step/time limits. runSkill visibly enforces timeout/output shape, not generic cost and step enforcement; Promise.race does not cancel underlying effects. Keep existing action-policy and provider readback, add scoped per-step guard only after proving atomic consumption and cancellation behavior.
- Current brain-loop.ts bounds time/tool calls and records model usage after calls. Add conservative model-call admission across all paths (not just this loop). cost-guard.ts checks monthly budgets with category estimates and separate recordCostEvent; avoid assuming check-then-insert prevents concurrent overspend.
- Current context-graph/recall.ts already limits items/chars/probes, checks owner scope and stale source refs. Use existing graph and evidence; add staged selective skill-node resolution only if evaluation wins.
- Existing SecondBrain lib/workspaces/access.ts and ask.ts enforce workspace role and pilot read-only semantics. #1660 dated facts adds separate private/workspace revision paths pending owner migration/release. Do not duplicate them.

## Phase 0 (this draft)
Pure projected-limit helper and synthetic fixtures for all dimensions, invalid/missing estimates, pending reservation, equality, overflow and already-spent state. Cost in integer micro-paise. No caller wiring; decision is NOT an atomic reservation, a price estimator, proof of successful execution or deployed safety control. CI list added. A known-free operation can have zero cost, but unknown price is blocked. Actual scope, trusted price/version, clocks and usage come from server, never model. Before production integration define one atomic durable reservation/settlement ledger over owner/workspace, subscription/department, job, run, attempt, and provider idempotency key. Preserve pending liability across retries, timeout and crash; reconcile unknown outcomes with provider evidence. Use conservative input/output/reasoning/tool and cache pricing bounds, FX and pricing snapshot freshness; reject unknown paid calls. Authorize each effect separately.

## Phase 1: governed budgets and execution (P0)
Use existing meter/cost guard, not parallel billing. Shadow record projected versus actual (include cache creation/read and actual served model); then guarded rollout with plan+turn+task limits, atomic reservation, settlement, wall-clock deadline and cancellation propagation. Test concurrent workers, fallback/retry, restart, unknown outcome, corrupt data, expired approvals, max tokens, exhausted spend and model price drift. No automatic cheap-model downgrade when capability/privacy requirements fail. For workspace costs only charge explicit workspace-authorized work; personal tasks remain personal.

## Phase 2: skill graph and executable contracts (P0)
Extend existing typed static registry, not arbitrary executable .og loader. Trusted schema: skill ID, version, concise routing metadata, typed nodes (trigger, prerequisite, evidence, step, assertion), scoped dependencies, bounded detail, allowed capabilities and approved handler IDs. Index -> dense candidate -> exact node + authorized dependencies. Enforce graph size, depth and cycles, ACL on every fetch and a no-match path. Fail closed on unknown assertions, handler IDs, versions or scope. Assertions are finite typed predicates over trusted observations; no eval, shell or model-provided dynamic imports. Validate preconditions, per-step constraints, exact approval and postconditions before reporting completion. No policy changes from learned content. Expose registry diff, provenance, owner, last verified date, usage and stale status. Start with inert calendar/meeting and workspace SOP fixtures; no live mutations.

## Phase 3: governed learning and memory lifecycle (P0)
Use existing decision-learning thresholds (20 samples, 0.82 guarded-live), do not relax them. Proposed skills remain draft, sandbox replay and independent review, explicit scope-specific activation, signed immutable version, auditable rollback. No self-authorized new capabilities, credentials or automatic external actions. Extend dated facts and existing semantic assertions with evidence and current/valid/recorded time, supersession, expiry, review and tombstones that suppress recall. Nightly bounded dry-run gardener only (no cron change in this PR). Auto exact dedupe only if identical scope, entity, claim, source semantics and lifecycle; contradictions, near duplicate, changed permissions and sensitive claims need review. Expiry must not resurrect old versions; deletion must remove derivative index/cache and queued refs consistent with existing erasure and retention policy. Never share private memories automatically. Untrusted email/web/connector data is evidence, not instructions; multilingual/encoded injection tests and quarantined promotion. Respect ACL and revocation at retrieval and execution.

## Phase 4: tools/model routing and observability (P1)
Lazy-load only authorized tool definitions; bound unlock operations and never infer consent from tool availability. Model capability/pricing registry and provider allowlist; use existing provider selection; evaluate response quality, India code-mix, model/region/data policy, latency, real usage and cache hit rate. Build run evidence views on existing dashboard: used/reserved/remaining, chosen skill version and retrieval provenance, policy/approval outcomes, pending reconciliation and failure reason; no private content, secrets, raw internal prompts or cross-workspace metrics. Use existing audit and test manifests; add Hachi-style regression bug bank with regression fixture per incident. Portable export only authorized content and provenance, no credentials or hidden instructions; schema version and retention control.

## Acceptance gates before enabling any real behavior
Compare staged retrieval with current architecture on a versioned personal+enterprise multilingual eval set, including irrelevant queries, ACL/tenant boundary, ambiguous retrieval, contradictory source and stale/revoked facts. No cross-tenant hits or unauthorized actions in adversarial fixtures. No increase in false completion, duplicate actions or approval bypasses. Measure actual token cost, p95 latency and quality vs current cached baseline; no claim of 98% savings. Require owner-scoped pilot, exact-head/merge-ref green CI, distinct independent CODE/SECURITY review, zero unresolved P1/P2, verified preview and owner gates. The current prototype has not activated any features. Hachi's 4,300+ reported tests are upstream, not our verified tests.
