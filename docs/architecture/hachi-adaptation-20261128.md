# Hachi adaptation — shared AskGogo / SecondBrain roadmap

Source: https://github.com/OpenGigantic/hachi (Apache-2.0 code; ObjectGraph specification/paper separate CC BY 4.0; trademark excluded). Architecture review as of 2026-11-28. The additions in this draft are independently written TypeScript reference implementations, not a fork, not a new service, and not enabled in production.

## Existing baseline and gap
Main 1322e29: typed static skill registry, capability policy, provider evidence, durable jobs, source-scoped memory and existing tests. The skill registry declares step, monetary and time ceilings; its wrapper checks policy/input/output and races a timeout, but does not itself reserve the declared cost/steps or guarantee cancellation of a provider action. Do not claim global enforcement from that wrapper. Dated facts #1660 remains separate and owner-migration-gated.

## First isolated slice
- Read-only skill discovery: compact index -> bounded preview -> exact version resolution, with current visibility rechecked each time. No skill installation, execution, permission grant or tenant-content retrieval. It uses existing trusted static definitions. Matching is deterministic token overlap; multilingual synonym routing, BM25/hybrid ranking, dependency traversal and eval calibration are future work. The caller must compute visibility from verified actor/workspace policy, never model output. Never treat a discovery hit as authorization.
- Process-local execution budget: reserve worst-case integer micro-INR per attempt before dispatch, count steps, reject unknown prices, enforce deadline, retain uncertain charges, freeze on underestimated spend. A reference implementation for tests only; it does not stop an in-flight call or supply durable/atomic distributed reservations. No runtime integration in this PR.

## Next slices, each behind reviewed contracts
1. Inventory every model, tool, retry, delegated worker, scheduled workflow and paid provider call. Integrate reservations at their actual shared boundaries; durable transactional owner/workspace/task/turn ledger, unique attempt IDs, replay/reconciliation and bounded retries. Unknown outcomes retain reservation; distinguish verified, incomplete and uncertain. Provider pricing/FX source, rounding, cached token pricing and output ceilings required. Owner/admin cap, per-tenant quotas, global ceilings, no unilateral limit elevation.
2. Extend existing skill registry with qualified immutable versions, structured summaries, typed dependencies and non-executable assertions. Rank authorized candidates before exposing metadata, use existing capability and exact-action approval gates immediately before execution. Add tenant-scoped catalog and audit receipts; shadow retrieval first; multilingual negative probes, ambiguous requests and adversarial input. Skills cannot grant tools, execute embedded code or promote themselves. Compare cost and task quality versus current router, not dump-all alone.
3. Build proposed-learning lifecycle atop current memory and skills: source/evidence, candidate diff, schema lint, deterministic tests, permission-delta check, owner/admin review, immutable revision publication, pinning/rollback, stale skill detection, provenance and tenant isolation. Ingested mail/web/docs/MCP results are untrusted data; never automatically promote instructions into durable memory or executable skills. Reuse dated-facts and existing consent/forget/export; no ChromaDB migration or oldest-first deletion of evidence. Separate personal, workspace, and agent procedure scope.
4. Connector gateway: registered tool schemas, actor and tenant-scoped OAuth, explicit egress/SSRF restrictions, connector identity/version/pinning, revocation rechecks, exact-action approval, sanitized outputs, receipts and bounded retries. Use existing browser/desktop controls; no arbitrary shell or unrestricted tier in shared cloud.
5. Engineering controls: add deterministic layer/import contracts, regression-first bug bank, CI fail-closed gates, secret scanning and dependency checks, independently reviewed release and rollback. Avoid raw sensitive traces. Surface budget, skill revisions, evidence, incomplete outcomes and approvals on Brain/SecondBrain admin. Preserve existing production routes and owner-only SQL/env/secrets.

## Acceptance
All changes start inert or shadow; independent code and security reviews, exact-head and composed CI and fixture build, then approved hosted acceptance. No real email/booking/payment/provider enablement without separate authorization. Test denial before dispatch, concurrent workers and cap races (distributed implementation), retries and unknown provider outcomes, revoked visibility between passes, cross-tenant data, stale approvals, prompt injection, version ambiguity, rollback and audit evidence. Benchmark retrieval recall/precision, false routing, p95 latency, tokens and actual cost per successful task. Hachi's first-party 98% skill-loading result is not a promised total-cost reduction.
