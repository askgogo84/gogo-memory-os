## Contract and acceptance

The model selects source IDs; code copies the supplied source excerpts. A model rewrite, invented quote, unknown source ID, owner override, role override, expiry override or verified-outcome flag cannot become a new chat-memory claim. Existing source timestamps, turn pointers and expiry survive repeated compaction. Old unsupported prose is withheld rather than assigned invented citations. The next eligible refresh rebuilds from available history.

This retains Mercury, the existing owner-bound `memories` JSON row, existing conversation history, background refresh and reply assembly. It adds no provider, schema, RPC, scheduler, router or tool permission. Vault secrets, saved preferences, documents and typed provider records keep their current stores and authority. The enterprise memory-scope plan is not implemented here.

## Limits and rollout behavior

- Maximum12 stored excerpts, 40 newly folded messages plus12 retained sources, 240 characters per supplied excerpt, 600 model output tokens and 1,500 characters of quote lines in the reply context. Excerpts are whitespace-normalized; they are not necessarily byte-for-byte copies of formatting. Turn IDs remain stored when available; missing IDs are explicitly null, with a derived fingerprint rather than a guessed message ID.
- Unsupported legacy summaries are still available as stored rows for reconstruction/audit but no longer enter the reply prompt. A successful source-backed refresh may clean up superseded summary rows through the existing owner-scoped policy. No backfill job or production cleanup ran in this engineering slice.
- A JSON selection failure leaves prior safe state intact and logs source-validation failure without raw source text. Withheld legacy or expired state means less historical context until a valid refresh; the recent20 messages and current saved/typed records remain available. Mercury's real selection-format reliability, recall quality, latency and token cost are not measured here. No improvement in those measures is claimed.
- The existing timestamp-only fold cursor, recent40 backlog window and100-summary-candidate saturation policy remain. Identical timestamps still need a message-ID cursor, and backlog ingestion can omit older history. Source-bound quotation is not complete long-term memory or complete ten-gate acceptance.
- Source ownership/provenance assumes the existing service-side storage boundary. It is not cryptographically authenticated against a privileged writer. The service-only memory-RPC migration already in #742 remains an explicit unapplied production dependency. This patch does not authorize applying it or any other migration.
- Fencing prompt text as data is not a complete prompt-injection defense. No new executor path is added; existing exact approvals, typed state, provider read-back and unknown-outcome handling remain required.
