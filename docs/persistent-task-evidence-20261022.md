No runtime, Same Brain, shared general planner, UI/router, browser, notification or migration file is changed.

Observable acceptance: a persistent `tasks.safe` step completes only after the existing canonical task executor acknowledges an owner-scoped read/create/reuse. Failed or ambiguous replies cannot count as task evidence. Failed reads retain bounded runtime retry/backoff; uncertain writes and lost completion checkpoints cannot auto-replay; duplicate workers cannot duplicate a task in the same run. Private-task permissions must remain enforced. This does not implement a complete uniform helper protocol.

## Remaining acceptance and handoff

- `files.read` and `travel.read` still use the opaque Same Brain fallback; their typed completion/evidence contracts are **unfixed**. This report does not clear those routes or the older general planner's generic fallback.
- Complete uniform helper lineage, isolated source contexts, per-helper tool budgets, cancellation propagation and durable child recovery remain open. Registry names are not helper agents.
- Existing persisted task rows retain their original conservative mutation flag. No migration/backfill changed production state. New task reads get read retry semantics; old task reads can still be quarantined on failure.
- Canonical task creation reuses the unchanged check-then-insert executor. Concurrent separate runs can still race to create duplicates; wildcard/case-matching semantics are inherited. The same-run CAS tests do not establish a database uniqueness constraint or independent post-commit readback.
- Unknown duplicate lookup remains bounded by 10 minutes and 20 recent rows; same-objective dedup is not permanent idempotency. Owner-initiated explicit reconciliation is still needed.
- Mixed/unsupported task intents fail conservatively rather than guessing or claiming partial success. Retry on a later user request is a new instruction, not automatic mutation replay.
- Source passing does not establish production behavior. Signed-in WhatsApp/dashboard task continuation, real DB response behavior, latency/cost and all broader ten-area/manual acceptance remain unverified. Source quotation changes from #743 retain their separate limitations.
- No component replacement, new model/provider, table, RPC, schema, dependency or runtime permission is introduced. No real sends, bookings, payments, credentials, merges, deployments or production DB changes are authorized by this slice.
